# 연결된 MCP 도구가 몰래 바뀌면, 이제 알아챌 수 있게 됐습니다

## What

MCP(Model Context Protocol)로 외부 도구를 연결해 쓰는 경우, 서버가 처음 알려준 도구 설명이나
입력 형식이 나중에 몰래 바뀌어도 지금까지는 알아챌 방법이 없었습니다. 이번 변경으로 "처음
승인했던 도구 정의"를 지문처럼 찍어두고, 나중에 그 지문이 달라졌는지 비교해서 알려주는 기능이
추가됐습니다.

## Where

`packages/ai/src/generate-text/tool-fingerprint.ts`(신규)에 핵심 함수 두 개
(`fingerprintTools`, `detectToolDrift`)가 들어갔습니다. 지문을 만드는 해시 계산 부분은 원래 도구
승인 서명 코드(`tool-approval-signature.ts`)에 있던 걸 `packages/ai/src/util/canonical-hash.ts`라는
공용 파일로 빼내 재사용하도록 정리했습니다. 사용법은 문서(`content/docs/03-ai-sdk-core/16-mcp-tools.mdx`)와
새 예제 코드(`examples/ai-functions/src/tools/mcp-tool-drift-detection.ts`)에도 같이 추가됐습니다.

## How

`fingerprintTools`는 도구 하나하나의 설명(description), 입력 형식(schema), 제목(title)을 모아
SHA-256 지문(digest) 하나로 만듭니다. 이 지문들을 "신뢰 시점"(사람이 도구 목록을 처음 검토했을
때) 기준값으로 저장해두고, 이후 MCP 서버에 다시 물어볼 때마다 `detectToolDrift`로 새 지문과
비교합니다. 바뀐 도구, 새로 생긴 도구, 없어진 도구를 각각 분류해서 알려주고, 그 결과로 무엇을
할지(차단할지, 재승인을 요구할지)는 서비스 쪽 판단에 맡깁니다.

흥미로운 디테일 하나: 도구 이름이 하필 `constructor`나 `toString`처럼 자바스크립트 객체가 원래
갖고 있는 속성 이름과 겹치는 경우까지 대비한 테스트가 따로 추가돼 있습니다. 단순하게
`baseline[도구이름]`으로 찾으면 실제 저장된 값이 아니라 자바스크립트가 기본으로 갖고 있는 값을
잘못 읽어올 수 있기 때문입니다.

비유하자면, 계약할 때 도장 찍은 계약서 사본을 보관해뒀다가, 나중에 상대방이 들고 온 계약서가 그
사본과 한 글자라도 다르면 바로 알아채는 장치를 마련한 것과 비슷합니다.

## Why

Diff에 같이 포함된 문서 파일에 이유가 비교적 분명하게 적혀 있었습니다: MCP 프로토콜 자체는
서버가 처음 승인받은 도구 정의와 다른 정의를 나중에 몰래 돌려줘도 막을 방법이 없고, 이런 공격을
"rug pull"(양탄자 빼기)이라고 부른다는 설명, 그리고 외부 보안 블로그(invariantlabs.ai) 링크까지
diff 안에 들어 있었습니다. 즉 "도구 설명에 몰래 지시문을 심거나 입력 형식을 몰래 넓히는 공격을
막기 위해서"라는 동기는 diff만으로도 비교적 뚜렷하게 읽혔습니다.

다만 "왜 하필 지금 이 기능을 넣었는지" — 실제로 이런 공격을 당한 사례가 있었는지, 특정 사용자
요청이 있었는지 — 는 diff에 없어서 알 수 없습니다. PR 설명이 있었다면 이 계기까지 확인할 수
있었겠지만, 이번엔 "기술적으로 왜 필요한 방어인지"까지만 자신 있게 쓰고 "왜 하필 이 시점인지"는
비워뒀습니다.
